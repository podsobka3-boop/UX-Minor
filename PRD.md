# PRD: «Делаешь?» — напоминалка о цели сессии за компьютером

> Версия 0.2 (промежуточная сдача ИДЗ1, 12.11.2026).

## 1. Идея

Садишься за компьютер «на пять минут ответить на письмо», а через час обнаруживаешь себя в ленте новостей. Приложение помогает помнить, **зачем ты сел за компьютер**, и вовремя остановиться.

Перед началом работы пользователь открывает приложение во вкладке браузера и записывает цель сессии, например «разгрести почту». Пока он работает, приложение время от времени ненавязчиво «тыкает»:

- «Делаешь „разгрести почту“?»
- «Не забыл про „разгрести почту“?»
- «Как там „разгрести почту“?»
- «Сделал „разгрести почту“?»

Когда пользователь отмечает цель выполненной, приложение хвалит и спрашивает: «Это всё, что ты хотел сделать?» Если да, показывает итог сессии и завершает её. Если нет, предлагает записать следующую цель.

**Чем отличается от таймеров и to-do:** это не планировщик и не Pomodoro. Здесь одна цель на «сейчас», вопросы вместо будильника и явное завершение сессии с итогом.

## 2. Для кого

| Персона | Ситуация | Боль |
|---|---|---|
| Студент | Сел делать домашку, открыл браузер «на минутку» | Теряет час на соцсетях, домашка не сделана |
| Человек на удалёнке | Вечером сел «только проверить почту» | Залипает до ночи, не может «закрыть» день |
| Человек с СДВГ-подобным вниманием | Много вкладок, переключается между задачами | Забывает исходное намерение через 10 минут |

Основной пользователь: один человек, который пользуется приложением сам для себя на своём ноутбуке или десктопе.

## 3. Функции (MVP, 5 штук)

1. **Цель сессии.** Поле «Зачем ты сел за компьютер?», кнопка «Начать». Можно добавить несколько целей, но активна всегда одна (первая невыполненная).
2. **Тыкалки (напоминания).** Приложение показывает вопрос с подставленной целью через **случайный** промежуток времени: по умолчанию от 5 до 20 минут, диапазон можно поменять в настройках (от 1 до 60 минут). Каждый следующий промежуток выбирается заново, поэтому к тыкалке нельзя привыкнуть и заранее «подготовиться». Сколько осталось до вопроса, не показывается. Формулировка выбирается случайно из набора, чтобы не приедаться. Канал показа: системное уведомление браузера (если пользователь разрешил), плюс карточка внутри вкладки и мигающий заголовок вкладки.
3. **Ответ прямо в уведомлении.** Отвечать на тыкалку можно кнопками в самом системном уведомлении, не открывая страницу: ответ занимает один клик и не уводит от работы. Браузер даёт не больше двух кнопок, поэтому их набор зависит от вопроса:
   - «Делаешь…?», «Как там…?», «Не забыл…?», «…в процессе?» → **«Делаю»** / **«Отвлёкся»**;
   - «Сделал…?» → **«Сделал!»** / **«Ещё делаю»**.

   «Делаю», «Отвлёкся» и «Ещё делаю» записываются молча, страница не открывается. «Сделал!» открывает вкладку сразу на вопросе «Это всё?», потому что дальше нужен выбор. Клик по самому уведомлению открывает вкладку с карточкой, где есть все три варианта. Ответ записывается в лог сессии. «Отвлёкся» не ругает, а просто возвращает к цели.
4. **Финал сессии.** После «Сделал!» появляется экран «Молодец. Это всё на сегодня?» с вариантами «Да, всё» и «Есть ещё дело». На «Да» показывается итог (сколько длилась сессия, сколько раз отвлекался), без советов и наставлений.
5. **Необязательный вход и история.** Пользоваться приложением можно сразу, без входа, в гостевом режиме. Кнопка «Войти» в углу открывает форму с именем и паролем (mock-авторизация, без сервера). При первом входе гостевые сессии переносятся в аккаунт. Вход нужен, чтобы на одном компьютере у нескольких людей была своя история. История прошлых сессий пользователя: дата, цели, длительность, число «отвлёкся».

### На потом (не в MVP)

- Ограничение сессии по времени («сижу не больше часа») с финальным напоминанием.
- Статистика за неделю, серии дней без залипания.
- Свои формулировки тыкалок и выбор тона: мягкий / строгий / с юмором.
- Тыкалки, которые учащаются, если пользователь часто отвечает «отвлёкся».
- PWA и уведомления при закрытой вкладке (через push-сервер).
- Интеграция с календарём или to-do (подтянуть цель из задач на сегодня).

## 4. Основной сценарий

**Начало → действие → результат**

1. Пользователь открывает приложение и сразу видит поле для цели. Вход необязателен: без него приложение работает в гостевом режиме, войти можно в любой момент кнопкой «Войти».
2. Видит экран «Зачем ты здесь?». Вводит «разгрести почту», оставляет диапазон по умолчанию 5–20 минут, нажимает «Начать».
3. Браузер спрашивает разрешение на уведомления (только при первом старте).
4. Экран «Идёт сессия»: крупно цель и время с начала сессии. Пользователь сворачивает вкладку и работает.
5. Через случайное время (например, 12 минут) приходит уведомление «Как там „разгрести почту“?» с кнопками «Делаю» и «Отвлёкся». Пользователь нажимает «Делаю» прямо в уведомлении, не переключаясь из почты. Уведомление исчезает, приложение выбирает новый случайный промежуток.
6. Через какое-то время приходит «Сделал „разгрести почту“?». Он нажимает «Сделал!» в уведомлении, и открывается вкладка приложения.
7. Экран «Молодец. Это всё на сегодня?»
   - **Да, всё** → экран итога: «Сессия 47 минут, 1 цель, отвлекался 1 раз». Кнопка «Завершить». Сессия попадает в историю.
   - **Есть ещё дело** → снова поле для новой цели, сессия продолжается.

**Ожидаемый результат:** пользователь сделал то, за чем сел, и увидел итог сессии. В истории есть запись о сессии.

### Экраны и состояния

| Экран | Состояния |
|---|---|
| Вход (необязательный, модальное окно) | закрыт (гость) / пусто / ошибка (пустое поле или неверный пароль) / вход выполнен |
| Новая цель | пусто (кнопка неактивна) / заполнено |
| Сессия идёт | ожидание вопроса / вопрос показан / пауза |
| Вопрос (карточка поверх сессии) | показан / отвечен |
| «Это всё?» | выбор |
| Итог | итог сессии |
| История | пусто («Тут будут твои сессии») / список |

Всё можно сделать одним экраном с переключением состояний; вход и история можно вынести в отдельные виды.

### Граничные случаи

- **Браузер не поддерживает кнопки в уведомлениях** (Firefox, Safari). Уведомление приходит без кнопок, клик по нему открывает вкладку с карточкой. Основной браузер для MVP — Chrome или Edge.
- **Уведомления запрещены.** Работают карточка в вкладке, мигающий заголовок (`(!) Делаешь?`) и необязательный звук.
- **Вкладка закрыта или перезагружена.** Сессия хранится в localStorage и восстанавливается при открытии. Тыкалки при закрытой вкладке не приходят, это ограничение MVP.
- **Вкладка в фоне.** Браузеры замедляют таймеры в фоновых вкладках (до раза в минуту), поэтому время вопроса проверяется по сохранённой отметке времени, а не по счётчику. Точность ±1 минута допустима.
- **Пользователь не отвечает на вопрос.** Карточка остаётся. Следующий вопрос не накапливается, а заменяет предыдущий.

## 5. Технические решения

| Что | Решение | Почему |
|---|---|---|
| Платформа | Веб-приложение в браузере, только десктоп | Ограничение задания; сценарий про компьютер |
| Стек | React + TypeScript + Vite | Быстрый локальный запуск, агенту привычен |
| Библиотека компонентов | Ant Design v5 (`antd`) | Готовые формы, модалки, ползунок-диапазон, уведомления, тёмная тема; выбор автора |
| Уведомления | `ServiceWorkerRegistration.showNotification()` с полем `actions` (кнопки ответа) + внутренние уведомления AntD (`notification`) | Кнопки в уведомлениях доступны только через Service Worker. Он ловит `notificationclick`, смотрит `event.action` и передаёт ответ открытой вкладке через `postMessage`; вкладка пишет его в localStorage. Сервер и push не нужны, работает на `localhost` |
| Хранение | localStorage | Один пользователь, один браузер, данных мало |
| Авторизация | Необязательный mock-вход: без входа работает гостевой профиль `guest`; имя и пароль хранятся в localStorage (пароль как хэш через `crypto.subtle`), «сессия входа» — флаг в localStorage | По заданию достаточно заглушки без внешних систем |
| Запуск | `npm install && npm run dev`, открыть `http://localhost:5173` | |

### Данные

```ts
User     { id, name, passwordHash, createdAt }
Settings { userId, minIntervalMin: number /* 5 */, maxIntervalMin: number /* 20 */, sound: boolean }
Session  { id, userId, startedAt, nextNudgeAt, endedAt?, status: 'active'|'finished', goals: Goal[], events: NudgeEvent[] }
Goal     { id, text, createdAt, doneAt? }
NudgeEvent { at, goalId, message, answer?: 'doing'|'distracted'|'done' }
```

Ключи localStorage: `zz.users`, `zz.currentUserId` (`guest`, если не вошёл), `zz.settings.<userId>`, `zz.sessions.<userId>`.

**Ограничения хранения:** данные живут только в этом браузере на этом компьютере. Очистка данных сайта их удаляет. Синхронизации между устройствами нет. Пароль защищает только от случайного входа, это не настоящая безопасность.

## 6. Границы проекта

**Входит:** один пользователь на устройстве (несколько аккаунтов возможны, но локально), одна активная сессия, тыкалки пока открыта вкладка, история сессий.

**Не входит:** сервер и база данных, настоящая регистрация, мобильная версия, блокировка сайтов, отслеживание того, что пользователь реально делает на компьютере, напоминания при закрытом браузере.

## 7. Как поймём, что работает

- Основной сценарий проходится от ввода цели до экрана итога без ошибок, и с входом, и без него.
- Тыкалка приходит в пределах выбранного диапазона (±1 минута), в том числе когда вкладка в фоне. Промежутки между тыкалками различаются.
- Ответ «Делаю» из уведомления записывается в историю без открытия страницы.
- После перезагрузки страницы активная сессия и история на месте.
- Для демонстрации есть «режим демо»: диапазон 5–15 секунд, чтобы показать тыкалку в минутном видео.

## 8. Принятые решения

- Цели: список, активна всегда одна.
- Тон тыкалок: неформальный, но ёмкий (см. DESIGN.md, раздел 7).
- Лимит времени сессии в MVP не нужен.
- Название: «Делаешь?».
- Время тыкалки случайное, по умолчанию 5–20 минут.
- Вход необязательный, есть гостевой режим.
- Ответ на тыкалку кнопками прямо в системном уведомлении.
